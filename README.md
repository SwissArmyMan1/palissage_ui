# Palissage web

Interface for direct B2B wine trade on Arbitrum Sepolia (421614) and Robinhood Testnet (46630): public catalogue, winery and shop cabinets, operator verification, primary escrow, resale royalties and delivery redemption.

**[Website](https://palissage.net/) · [Guided simulation](https://palissage.net/demo) · [Network status](https://palissage.net/network) · [Contracts and deployment evidence](https://github.com/SwissArmyMan1/palissage)**

## Run

Node.js 22+ is recommended.

```sh
npm ci
npm run dev
npm run lint
npm run build
npm run preview
```

React, TypeScript, Vite, wagmi and viem are used. English and French copy are supported. Production hosting must serve `index.html` for client-side routes; `vercel.json` includes the rewrite.

## Networks and payment assets

The network page and testnet-readiness page expose network selection. `?chain=421614&asset=eure` selects official Monerium test EURe on Arbitrum Sepolia; `?chain=421614&asset=eur` selects the separate Palissage tEURe faucet token; `?chain=46630&asset=usdg` selects Robinhood/test USDG. Monerium EURe is the default for a new Arbitrum session. The choice is retained locally. Switching starts a fresh readiness page and discards unfinished forms. Selecting EURe on Robinhood falls back to tEURe because Monerium has not published an official Robinhood address. There is no token or inventory bridge.

`EURe` uses Monerium's [official Arbitrum testnet address](https://monerium.com/eure/), `0xFdEed5cE7E281B4e0F163B70eBe2Cf0B10803b7B`, with 18 decimals. To obtain it, link a wallet on Arbitrum Sepolia in the [Monerium sandbox](https://docs.monerium.com/sandbox/), then use Receive → Add money. This test token does not represent real euros. No Monerium API, IBAN or bank-payment flow is embedded in Palissage.

`tEURe` remains a separate 18-decimal, valueless Palissage demo token with a daily on-chain faucet. `USDG` is the official Paxos 6-decimal test token, available from the [Paxos faucet](https://faucet.paxos.com/). Prices preserve the asset stored in each offer; choosing EURe or USDG does not convert existing offers, allocations or escrow.

The existing markets were configured to allow EURe without redeploying or changing Solidity sources. The live EURe fixture on Arbitrum Sepolia is lot/offer 8, allocation 6, listing 4 and redemption 5: 12 bottles minted, 3 resold and redeemed, 9 remain. Primary payment, seller proceeds, fees and the winery royalty were checked against ERC20 balance changes. [Public EURe execution evidence](https://palissage.net/evidence/arbitrum-sepolia-eure.json) contains all 20 transaction hashes and accounting results; its source is `public/evidence/arbitrum-sepolia-eure.json` in this repository.

`src/chain/deployments.json` is generated by the contract repository after receipt, bytecode and wiring verification. The browser does not accept arbitrary deployment-address overrides. `.env.production` contains public browser configuration only; `.env.example` lists optional chain-specific RPC URLs and WalletConnect project ID. Never put wallet keys or private provider credentials in `VITE_*` variables.

Before a live write the interface checks the actual RPC network, runtime code hashes, Lens wiring and enabled payment metadata, switches the wallet, simulates the call and requests one transaction. Confirmed receipts refresh both single and batched reads. A submitted hash is retained across reload; uncertain outcomes must be checked before another submission. All explorer links use the selected network.

## Demonstration and roles

The guided tours use a local simulation with a persistent banner. They require no wallet and submit no blockchain transactions. The live testnet workflow requires a real wallet and test ETH. Gateway test mode allows Winery, Shop and Consumer self-service; it never grants Admin. Token, primary-market and redemption verifier roles are independent. The interface shows the privileges actually held by the connected address.

Core write flows are wired to the contracts: lot creation/metadata/production, verification, offers/milestones, primary reservation/full settlement/cancellation/default, withdrawal, listing/update/cancellation/purchase and redemption/shipment/delivery/refund. Registry configuration, signed-claim issuance, treasury changes, force transfers, freezes and signed escrow recovery are operator contract APIs; they do not each have a public dashboard button. PalissageLens is read-only, so no user transaction to it is expected.

Public lots and simulation records are fictional. Test roles do not establish real KYC/KYB, wine provenance or commercial adoption. The prototype is not approved for real-value settlement.
